# Security review

Scope: the iPhone app, the watch app, both widget extensions, the `Tools/`
scripts and the three GitHub Actions workflows. Zoon has no server, no
account and no network code, so there is no web service to scan. The dynamic
testing here targets what an attacker can actually reach: the parsers that
read input from outside the process.

## Result

| Area | Method | Found | Fixed |
|---|---|---|---|
| Secrets | gitleaks 8.21 over all 768 commits on every branch; detect-secrets over the tree | 0 leaks. 5 detect-secrets hits, all false positives (Xcode scheme IDs, a purpose string) | — |
| Dependencies (SCA) | Inventory of imports and manifests | No third-party packages. Every import is an Apple framework; `Tools/` uses only the Python standard library. The one external supply chain is GitHub Actions | Actions pinned to commit SHAs; Dependabot keeps them current |
| CI workflows | semgrep `github-actions` rules, actionlint, manual review | 2 injection paths, unpinned actions, default token scope, secrets pasted into scripts | All fixed (below) |
| App code (SAST) | semgrep `swift`, `python`, `bash`, `secrets` rule packs (local copy of semgrep-rules), manual review of every entry point | 5 issues (below); 12 semgrep findings triaged as not applicable | All fixed |
| Untrusted input (DAST) | Seeded fuzz tests in CI | No traps found; each parser refuses or safely handles random and mutated input | Tests kept as regression |

## Findings and fixes

### CI

1. **Code injection in Screenshots.** The `device` dispatch input was pasted
   into Python source inside `'''` quotes, so a crafted name ran as Python on
   the runner. It is now read from the environment.
2. **Shell injection surface in TestFlight.** `build_number` (free text)
   and `free_certificate_slot` were substituted into shell scripts, and so
   were the App Store Connect secrets. Inputs and secrets now arrive as
   environment variables only. `build_number` must match a version pattern,
   and the key ID must be Apple's 10-character form before it names a file.
3. **Token scope.** Build and TestFlight now run with
   `permissions: contents: read`. Screenshots keeps `contents: write`,
   because it commits the captures.
4. **Unpinned actions.** `actions/checkout`, `upload-artifact` and `cache`
   are pinned to commit SHAs. `.github/dependabot.yml` proposes updates.
5. **Signing material.** The App Store Connect key is written owner-only
   (`umask 077`) and removed in an `always()` step at the end of the job. The
   cached signing identity stays encrypted with `IOS_P12_PASSWORD`, as
   before.

### App

1. **Siri on a locked phone.** "Get Recovery", "Get Sleep Summary" and "Get
   Tonight's Bedtime" spoke health data, and "Log Sleep Tag" wrote to the
   journal, without unlocking. All four now set
   `authenticationPolicy = .requiresAuthentication`.
2. **CSV formula injection.** The CSV `source` column is the name an app gave
   itself when it wrote to Health. A value starting with `= + - @`, tab or CR
   ran as a formula in Excel, Numbers or Sheets. Such cells get a leading
   apostrophe (OWASP guidance). Covered by a test.
3. **Backup key derivation.** PBKDF2-HMAC-SHA256 went from 210,000 to 600,000
   iterations for new archives, OWASP's figure for this PRF. Old archives
   still open, and new archives still open on older builds (their accepted
   range already reaches 1,000,000). Encryption is now **on by default** for
   JSON backups. A test checks that a header edited to fewer rounds is
   refused.
4. **Watch packets.** A packet's target night must be within 14 days before
   to 1 day after its own tap. The de-duplication receipt list is capped at
   5,000 instead of growing with every tap. Covered by a test.
5. **Log hygiene.** An evidence ID generated by the on-device model was
   logged as public text. It could echo user content, so only its length is
   logged now.

### Checked and sound

- **Backup crypto.** AES-GCM, a fresh random salt and nonce per export, the
  derived key zeroed after use, tamper and wrong-passphrase rejection
  (tested). The import is capped at 64 MB and validated all-or-nothing before
  any write.
- **Network.** No `URLSession`, web view or socket. The only URL opens go to
  the Settings app. No ATS exceptions. No pasteboard access.
- **Voice journal.** Requires on-device speech recognition and refuses to run
  without it.
- **Snore Check.** Audio is classified live and never written to disk.
- **Notifications.** No durations or scores in Lock Screen text.
- **Spotlight.** Screen names only, never health data. A search result can
  route only to an exact known destination (fuzzed).
- **Logging.** The other 50 `privacy: .public` interpolations are error
  descriptions and fixed identifiers.
- **Data at rest.** iOS default protection (encrypted until first unlock).
  Exports are written with `.completeFileProtection`. Full `.complete`
  protection would break the Lock Screen widgets and HealthKit background
  delivery, which read and write while locked.
- **Privacy manifests.** Present for all four targets. The code uses no
  required-reason API beyond UserDefaults, which is declared.
- **Crash surface.** No force unwraps, `try!` or `as!` in shipping code.
  Ranges built from data are guarded.

### semgrep findings triaged as not applicable

`insecure-random` (7): statistical bootstraps and a preview; deliberately
seeded for reproducible results, with no security role. `md5` (1): stable
Xcode object IDs in the project generator. `defusedxml` (2): parses this
repo's own scheme files. `dynamic-urllib` (1): a fixed App Store Connect
URL, using the default verified TLS context. `add-mask` (1): masks a
generated keychain password, which is the intended use.

## Fuzz tests

- `DataExporterTests.testFuzzedArchiveBytesAreRefusedOrFullyValid`: 600
  mutated backups (byte flips, truncation, splices, extreme or mistyped
  numbers, noise). Each is refused, or passes every validation rule.
- `UntrustedInputFuzzTests`:
  - encrypted envelopes: noise, forged salts, iteration counts and
    ciphertext;
  - watch packets: noise, mutations, extreme dates and bad time zones;
  - Spotlight identifiers.

All are seeded, so a failure reproduces exactly.

## Not in scope, or needs a device

- Jailbroken-device threats and runtime tampering: outside what an App Store
  app can defend against meaningfully.
- Keychain use: none. There are no credentials to store.
- A penetration test on hardware (Siri lock behaviour, Lock Screen widgets,
  AirDrop of an export). The unlock requirement relies on the App Intents
  runtime and should be confirmed on a locked device in TestFlight.
